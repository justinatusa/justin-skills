# 项目架构与运行流程地图

来源（原样收录）：https://gist.github.com/linearuncle/f9e22e01477c44c328f8e34103ec5fd2  
相关讨论：https://x.com/LinearUncle/status/2105506429788422409 · https://x.com/robinebers/status/2105309987983745060

以下正文为 Gist 中提示词原文，未改写。

---

请阅读当前项目，为我制作一个可交互的“项目架构与运行流程地图”，帮助我理解这个项目现在实际如何运转。

项目不断迭代，我可能已经失去对整体结构的把握。请从真实代码、配置和现有资料出发，梳理主要模块、业务对象、依赖关系，以及关键操作发生后的完整流程。

不要只输出文字报告；请实现一个可以打开并探索的可视化成果。

## 一、先理解项目

1. 识别项目的主要入口、核心模块、数据存储、外部服务和后台任务；只包含项目实际存在的部分。
2. 说明每个核心模块的职责，以及它与其他模块的关系。
3. 梳理主要业务对象：它们何时创建、如何关联、由谁读写，以及状态如何变化。
4. 从代码中识别最重要的 3—5 个用户操作或系统事件，作为流程演示场景。若我指定了场景，优先使用我指定的场景。

可选补充：
- 我最关心的操作或场景：[填写；留空则自行识别]
- 我目前不理解的关系或行为：[填写；留空则自行梳理]

## 二、追踪实际运行流程

对每个关键场景，按照发生顺序解释：
- 什么触发了这个流程；
- 哪个模块接收并处理；
- 调用了哪些其他模块或外部服务；
- 哪些数据被创建、读取、修改或删除；
- 是否涉及异步任务、事件、队列或回调；
- 最终结果如何返回或呈现；
- 代码中已有的失败处理、重试和分支是什么。

明确区分同步调用、异步处理和数据流。连线应标明方向及含义，不要只把模块连接起来。

## 三、实现交互式地图

请提供：
- 可缩放、平移和重置视图的画布；
- 整体概览，以及可以展开的模块细节；
- 可点击的节点，展示职责、关联对象和相关代码位置；
- 可选择的关键场景；
- “上一步 / 下一步”流程演示；
- 每一步高亮当前涉及的节点和连线，并用中文说明正在发生什么。

优先保证可读性。不要把所有文件都画成节点，也不要把全部细节塞进一张图。先让我看懂全局，再逐层查看细节。

## 四、保证事实可信

- 每个关键模块和流程关系都应能追溯到代码或配置，提供文件路径及函数、类或其他定位信息。
- 区分“已确认的事实”“有依据的推断”和“尚未确认的部分”。
- 文档与实现不一致时，以当前实现为主，并指出差异。
- 无法仅靠静态代码确认的运行时行为，请注明需要什么证据。
- 不要为了让图完整而编造模块、调用关系或处理步骤。
- 不要把建议中的架构画成现有架构。

## 五、交付与验收

选择适合当前项目的简单实现方式，并说明如何打开或运行。将架构数据、流程步骤与展示逻辑适当分离，便于后续更新。

本次任务聚焦于理解和可视化现有项目，不主动重构业务逻辑。

完成后检查：
1. 关键场景是否覆盖了从触发到结果的全过程；
2. 图中的关系是否有实际依据；
3. 缩放、节点点击和步骤切换是否正常；
4. 是否清楚展示了尚未确认的部分。

最后用中文简要说明：项目整体如何运转、我最应该理解的几个关系，以及仍需核实的问题。
